A catalog that looks after itself

This site's catalog has been lost twice — once to a bad edit, once to a broken deploy. Both times it was back within a day, because a set of small automated jobs had been built around it with Claude. None of it required writing code by hand. The same recipe works for books, watches, wine, or trading cards.

01Start with the data

Tell Claude what you collect and which fields matter — condition, year, what you paid, what it's worth now. From that description it can build a spreadsheet or a small site like this one. An existing messy list is a fine starting point; cleaning it up is the kind of chore Claude handles well. Plan on an afternoon, most of it spent entering items.

02Add market prices

A scheduled task — a saved instruction that runs on its own, weekly in this case — looks up marketplace prices (Discogs for records; eBay sold listings cover most other hobbies) and stores low, median, and high next to each item. The catalog header now shows a running total, around €2,200 at the moment.

Expect a few bad matches in the first runs. Each one needs to be pointed at the right listing once; after that they stay fixed.

03Nightly backups

A second task exports the full catalog to a dated file in a GitHub repository every night. Recovery after the second data loss consisted of pasting the previous day's file back in — about ten minutes of work.

04A daily health check

The last piece is a daily check that only reads, never writes. It counts the records, verifies the prices are still present, confirms last night's backup actually exists, and compares the live catalog against it. When everything is fine it reports one line. When something is off, it says what's missing, what it expected, and which file to restore from. It deliberately has no ability to change anything — repairs stay manual.

05Chat, Cowork, or a schedule

Everything above was built through three modes of the same product, and knowing which one to reach for saves real time. Chat is for deciding: what fields to track, which grading system to use, drafting text like this page. Cowork is for doing: it works with files, a browser, and this site's repository, and it built every page and feature described here. Scheduled tasks are for repeating: anything you would otherwise have to remember to do nightly or weekly. A typical feature starts as a chat conversation, gets built in a Cowork session, and ends as a schedule that runs without you.

06Notes from running it

Build in the order above — each step is useful even if you stop there. Keep automated jobs read-only wherever possible; on this site, the jobs that can write are the ones that have caused incidents. And don't expect the first version to be right in every detail. The point of the backups and the daily check is that a mistake costs a day, not the collection.
