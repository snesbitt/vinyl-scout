The Vinyl Scout

How it works · v25 charter · July 2026

A pocket catalog for a personal record collection.

The Vinyl Scout tracks one person's vinyl collection: what's owned, its condition, what each pressing is worth, and which exact edition it is. It pulls real pricing and pressing data from Discogs, and plays a short preview of each album's most popular track. No accounts, no third-party tracking, no automation that quietly deletes data.

This page is the reference: what this catalog does today, its data model, and its stack. For the method behind it — and the prompt to build one for your own collection — read the Guide instead.

01What it is

A catalog for one person's records. The owner photographs covers in small batches. Claude reads each cover and identifies artist and title, and a short list of Artist - Title lines gets pasted into /seed.html to register the records. Every entry is editable on /audit.html.

Each record is enriched with Discogs data: accurate pressing ID, marketplace prices (low, median, high from sales history), community ownership and wishlist counts, and ratings. The lowest price refreshes on demand, either one record at a time or in bulk. Median and high prices come from a browser-based lookup, since Discogs blocks automated requests for that data; refreshing the low price never overwrites them.

The collection page itself, what you came from, is read-only: anyone with the link can search and filter by genre, but not edit. Switch between a gallery view (cover art, artist, and title) and a list view, which also shows each record's low, median, and high price. The header names the single highest-value record, just below the total collection value. Tap any record to see the full detail: the complete Discogs snapshot, the community rating, and, where available, a Play button for a preview of the album's most popular track.

02The stack

The plumbing, for anyone who wants it. Skip ahead if you don't.

  • Frontend. Static HTML, CSS, and one JavaScript file. No framework, no build step. Served from Netlify's CDN.
  • Storage. A single Netlify Blobs store called records. One JSON blob per record, keyed by ID.
  • API. Netlify Functions v2. Records: GET (list) · POST (upsert by ID) · DELETE (single), gated by an edit key. Wishlist: the same trio at /api/wishlist, backed by its own Blobs store so wishlist writes can never touch the catalog; POST/DELETE here are intentionally open, no edit key, since re-entering one on mobile every session wasn't practical for a page used casually. Enrichment: /api/discogs/lookup (match by artist/title, public), /api/discogs-pricing (fetch + store pricing, gated). Audio: /api/audio/preview (most-popular-track preview lookup, public, read-only, using Deezer first, with a small per-title override list for best-of/compilation albums Deezer doesn't carry under their own name, then YouTube as a last resort for the rest).
  • Source. Plain Git repo at github.com/snesbitt/vinyl-scout. Every change ships via git push; Netlify rebuilds in under a minute.
  • Authoring. Code and copy written collaboratively with Claude; deploys reviewed and run by the owner.

03The catalog record

Every record is one JSON object. Phase 1 fields are the originals; Phase 2 (live) adds Discogs enrichment: condition, accurate pressing ID, marketplace pricing, community data, and ratings.

  • id: opaque 16-character hex string (e.g. rec_a1b2c3d4e5f60718).
  • artist, title: required strings.
  • year, genre: optional. Year is 1900–2100.
  • cover_url: optional image URL or inline data URL.
  • notes: optional free text.
  • condition: Goldmine grade (default VG). See below.
  • price_low, price_median, price_high: market prices in price_currency, optional. Low is the current cheapest listing; median and high are from the release's last-30-sales history.
  • price_last_sold: string date of the most recent completed sale (e.g. "Apr 23, 2026"), or null if the release has never sold.
  • copies_available: count of copies currently for sale, optional.
  • have_count, want_count: Discogs community ownership and wishlist counts, optional.
  • rating_avg, rating_count: Discogs community rating (0–5) and number of ratings, optional.
  • price_currency: ISO code (USD, EUR, GBP), optional.
  • price_updated_at: ISO timestamp of last refresh, optional.
  • discogs_release_id: cached release ID for fast refreshes, optional.

04Condition grades

Vinyl Scout uses Goldmine grading (the US standard for record sleeves and discs). Each record stores its own condition code. Default is VG (Very Good).

  • M: Mint. Never played, still sealed or in perfect condition.
  • NM: Near Mint. Played once or twice, looks and sounds unplayed.
  • VG+: Very Good Plus. Minor wear; fully playable with no defects.
  • VG: Very Good. Light surface marks, plays without issue.
  • G+: Good Plus. Noticeable wear, plays through, some surface noise.
  • G: Good. Significant wear, plays but with some noise.
  • F: Fair. Heavy wear, plays but may skip or have extended noise.
  • P: Poor. Severely damaged, barely playable.

05Wishlist

A separate hunt list at /wishlist.html, kept apart from the collection. Records arrive three ways: added by hand (cover art and a Discogs reference are looked up automatically), imported from Spotify (a weekly sync reads the owner’s most-played albums, keeps only the ones on vinyl, and skips anything already owned), or imported from the owner’s Amazon cart (the same weekly sync reads it, and never changes it).

Each row shows the album art, the current asking price or Discogs’ median sale price, and a link to current listings. A brand-new item shows no price at all until the following Monday's scout run.

Adding and removing items needs no edit key. It's the one part of the site left open, since re-entering one on mobile every session wasn't practical for a list used this casually. The collection itself stays fully gated.

The weekly scout refreshes prices. Nothing is auto-removed, and anything deleted by hand is never auto-re-added.

A note on ordering, in the same spirit as the pricing data above: today the list sorts alphabetically by artist and nothing else. There is no ranking by value, rarity, or how long something has been on the list, and no hidden scoring behind it. A real priority system is on the roadmap; see Phase 9 for what that would take.

06Audio preview

Every record's detail view has a Play button. It fetches the album's most popular track and plays a short preview clip in place. It looks up the track on Deezer first, no sign-up needed. A small hand-picked list covers best-of and compilation albums that aren't on Deezer under their own title, pointing to a representative single from the same artist instead. YouTube is the last resort, for anything genuinely absent from Deezer. A credit line under the player names the source. It's a pure lookup: nothing is stored. If nothing anywhere has a match or a playable clip, it says so quietly.

07Data & backups

Every record is backed up automatically. A nightly job commits the whole catalog to backups/YYYY-MM-DD.json in the GitHub repo. A backup can also run on demand.

The catalog is read-only for the public; anyone can browse it. Edits require an edit key. There are no user accounts.
